- **Live (2026-10-04):** the setting, file, version, or service state was checked on that date.

Security-sensitive remote-access items are described only as capabilities. Their pairing, addresses, firewall scope, and exposure paths are not published. Provision them privately on a new machine.

**Shift+Left/Right selection is rebuilt automatically** (Both, since 2026-09-29; Live). Stock OMP still lacks input-line selection. The marked `omp()` block in `~/.bashrc` runs a private build `~/.local/share/omp-integrations/shift-selection-<version>/` only when `<version>` equals mise's selected stock version; `command omp` bypasses it, and stock binaries are never modified.

- If the build for the current version is missing, the launch uses stock OMP, prints one notice, and starts a detached, single-flight `shift-selection-patches/ensure.sh <version>`. It first probes stock OMP in an isolated terminal; if stock already supports selection, it writes `<version>.native` and stops. Otherwise it downloads the upstream tag, three-way merges the two patched editor files (any conflict fails), runs the focused tests and type check, compiles, runs an isolated selection test, and installs only the new binary. A rebuild took about one minute on each machine. New launches pick it up; running sessions need `exec bash`, then `omp -c`.
- State lives in `~/.local/state/omp-shift-selection/` (`<version>.log`, `.failed`, `.native`, `disabled`, `audit/`). A failure leaves stock OMP in use, writes `.failed`, and sends one notification. It is not retried automatically; after fixing it, run `ensure.sh <version> --force`. Pause rebuilds with `touch ~/.local/state/omp-shift-selection/disabled`.
- Builds exist for 18.6.0 on both machines. The Mac's 18.6.1 build had not been created yet when this report was written; the next interactive launch triggers it. (Open)
- Build each machine natively. Never copy these binaries across architectures. Old builds are not pruned.

## 3. Appearance: the rig follows the Mac's theme

**Theme sync** (2026-10-03; Live). The Mac's Omarchy theme is the source of truth. Both machines now use the stock Omarchy theme **Lumon**; older reports say the Mac uses Blueridge Dark and the rig Tokyo Night.

- On the Mac, the user unit `omarchy-theme-sync.path` watches `~/.local/state/omarchy/current/theme.name` and starts `omarchy-theme-sync.service`, which runs `~/.local/bin/omarchy-theme-sync push`. `omarchy-theme-sync-catchup.timer` (30 s after login, then every 2 min) runs `push --if-pending`, which connects only when the Mac theme differs from the last theme synced, so a change missed while the rig was offline syncs later.
- `push` runs `omarchy-theme-sync apply <theme>` on the rig over SSH with batch mode and strict host-key checking. On the rig, `apply` runs `systemd-run --user --wait omarchy-theme-set <theme>`, so the theme is applied inside the graphical session, including the theme-set hook that updates the prompt and OMP themes. If the rig lacks the theme, `push` copies it to `~/.config/omarchy/themes/<theme>`; it never overwrites an existing directory. No sudo and no keybindings are involved.
- A manual theme change on the rig stays until the Mac's theme changes next. In the end-to-end test, the rig followed a Mac switch in about 6 seconds.
- Check: `omarchy-theme-sync status` (Mac); logs: `journalctl --user -u omarchy-theme-sync -u omarchy-theme-sync-catchup`.
- Disable: `systemctl --user disable --now omarchy-theme-sync.path omarchy-theme-sync-catchup.timer` on the Mac. To remove it, also delete the four `~/.config/systemd/user/omarchy-theme-sync*` units and `~/.local/bin/omarchy-theme-sync` on both machines.
- A new machine needs a working SSH route from the Mac role to the rig role with a pinned host key. Provision it privately.

## 4. Remote streaming and input on the rig

- **Mouse speed over Moonlight** (Rig, 2026-09-29; Live). The Mac's trackpad arrives on the rig as Sunshine's virtual mouse, already accelerated by the client, so Hyprland's adaptive curve doubled it. `~/.config/hypr/input.lua` now sets, for the device `libvirtualhid-mouse`, `accel_profile = "flat"` and `sensitivity = -0.5`. Local mice are unchanged.
- **Patched Sunshine** (Rig, 2026-09-30; Live). During long idle streams, GPU memory that no process claimed grew until hardware encoding failed. A local test showed the likely mechanism: while the captured monitor is powered off by DPMS, the compositor never finishes screen-copy requests, and a client that keeps re-requesting and replacing its buffers leaks memory. This was reproduced outside Sunshine, not measured inside it; it remains the leading explanation, not a confirmed root cause. Upstream pull requests #5748 (one capture request in flight) and #5764 (close the render-node file descriptor) cover the likely fix.
  - The rig now runs a user-local Sunshine build with those two pull requests applied, started through the drop-in `~/.config/systemd/user/app-dev.lizardbyte.app.Sunshine.service.d/10-patched-sunshine.conf` with `capture=wlr`. The packaged Sunshine stays installed as the fallback.
  - Rollback: delete the drop-in, run `systemctl --user daemon-reload`, and restart the unit. Restarting drops any active stream; do it only with the user's approval.
  - If GPU memory fills again, compare used memory with the GPU process list and check the monitors' DPMS state before restarting Sunshine.
  - Drop the local build once an upstream release contains both fixes.
- **Phone access** (Rig, 2026-10-02; Recorded). The rig's phone relay for Herdr was updated from 0.22.3 to 0.22.6, which includes an upstream fix so that idle agents show a green status dot. The previous release is kept for rollback. The Mac does not run the relay. Pairing and exposure are private.
- **Notification taps** (Both, 2026-09-30; Recorded). An attempt to make notification taps open the Herdr phone relay instead of the previous web terminal failed on the phone at that time and was reverted on both machines. Taps still open the previous route.

## 8. Agent working rules

Added to `~/.omp/agent/AGENTS.md` on both machines (Recorded):

- **JEV first for browser steps** (2026-09-29). Try the JEV bridge first for every browser step, including opening task pages and sign-in pages. Use another route (Browser Relay for reading page text, `xdg-open`, the native browser facade, CLI/API) only for a step JEV cannot do, and say which step and why. Whether to keep this rule now that the relay exists is still a [pending user decision](../control-stack/RESULTS.md#needs-the-users-decision).
- **Self-testing before handback** (2026-09-29). Agents test front-end work end to end in a real browser themselves (JEV first, then the native browser facade) and never ask the user to check something they can observe by another route. Development happens on the rig; when the user must see a UI, make it reachable in the Mac's browser instead of opening it on the rig.
- **Check real tab state** (2026-09-30). Before reporting on or instructing another Herdr/OMP tab, read its latest summary and current status; never infer state from a keyword search of older output. If the state is unclear, say so.
- **Protect the rig's Claude login** (2026-09-30). Never log out, disable, revoke, copy, or hand-edit the Anthropic subscription login in OMP's credential store on the rig, and never start a second refresher over the same store. Automated coding runs on the rig use that subscription model; the OpenRouter credential is for JEV decisions, not for planning (correction, 2026-10-03). After any change near OMP authentication, check from metadata only that the login is still enabled and refreshing.
- **Rate-limit IP rotation** (2026-09-29, updated 2026-10-03). When authorized work hits external rate limiting or bot checks, the agent may switch that machine's VPN exit node (through Tailscale) to another privacy-preserving country and retry, keeping LAN access on and verifying the new exit afterward. Isolated download refusals are retried once instead. On the rig, changing the exit node needs sudo, entered by the user in a Herdr pane below the agent. This does not allow sign-in, age-gate, or paywall bypasses or unbounded retries. In a later test, every rotated exit was bot-checked; whether those exits were flagged or the downloader was outdated was not tested.
- **Reverse-engineering tool suggestion** (2026-10-04). When the user asks to reverse engineer something, suggest REA (`morluto/rea`, npm package `rea-agents`, needs Node.js 22.19+). It is not installed; ask before installing and review what `rea setup` changes first.
- **Zig for from-scratch rebuilds** (2026-10-04). When rebuilding something from scratch after reverse engineering it, use Zig by default and say so in the plan, unless the user asks otherwise or a concrete constraint requires another language. Existing projects keep their language.
- **Remote process matching** (lesson, 2026-10-04). Inside `ssh host '...'` or `bash -c '...'`, `pgrep -f` / `pkill -f PATTERN` also matches the wrapping shell's own command line; this killed SSH sessions. Match by exact PID, by `pgrep -x <name>`, or with a bracket pattern such as `[P]attern`.
- **Home directory organization** (2026-10-04): see section 7.
