## 1. FIRSTMATE tracker and dashboard (rig)

FIRSTMATE is the coordinating agent session. The owner talks mainly to FIRSTMATE; it keeps a tracker of every
request, job, open question and decision, and shows it on a mobile web page.

- **Card states** (owner decision, final on 2026-10-18; Live in the `fm` CLI):
  - ✍️ **Needs you** (`waiting`): an action only the owner can take. Shown first in every view, with a link to
    the question or the source message.
  - ⚠️ **Open** (`open`): only an unanswered owner question. The CLI refuses this state without a question link.
  - 🔧 **In progress** (`partial`): answered or accepted and queued, with no live job.
  - ⚙️ **Running** (`running`): a live job works on it now. The CLI refuses this state without a `job` field (a
    Herdr tab or pane, or a systemd unit).
- **Deep links** (Recorded; contract file next to the page): `?item=<id>`, `?tab=needs|open|progress|running|reports|done|all`,
  `?since=<epoch ms>` (with optional `&by=run:<id>`), `?q=<search>`, `?report=<path>`. `since` shows a
  "Changed in this reply" strip. The `report` value accepts only dashboard paths on the same host; other values
  are refused.
- **Live refresh** (Recorded): the page re-reads the tracker every 10 s and redraws when the file changes.
- **Tabs** (Recorded):
  - Items, with filters for each state, dependency chips (`Blocked by`, `Unblocks`) that jump between cards, and a
    collapsed Done group.
  - 📚 Reports: every report page, PDF, audio file and status note under the report folder. Reports open in a
    full-screen viewer inside the page.
  - ⚙️ Running: agent jobs from Herdr (title, tab, last activity; "do not interrupt" while working) and background
    services. Services are grouped in a collapsible accordion (one section per group; groups with a failed unit
    open by default). The generator only reads; nothing on the page starts or stops a service.
- **Home Screen app** (Live: manifest served): web-app manifest and icons, so the page can be added to the iPhone
  Home Screen. Not tested on a real iPhone.
- **`fm` CLI** (Live): the only supported way to change the tracker. It takes an exclusive file lock, re-reads the
  file and changes one item per write, so parallel agents do not overwrite each other. Every write records who
  made it (`by`: run id, Herdr pane, `autoclear` or `manual`) and keeps the last 5 writers.
- **`fm-autoclear`** (Live: `fm-autoclear.timer`, every minute): deterministic rules with no model calls. It closes
  a card whose linked status file says the work is done, moves answered questions out of Open/Needs you, moves
  cards between In progress and Running from live job state, flags cards whose job ended without a report, and
  flags owner cards with no question or source link. It never deletes cards and never changes trading cards or
  time gates. Self-test: `fm-autoclear --test`.
- **In-progress sweep** (Live: `firstmate-sweep.timer`, every 2 h): `fm-autoclear` lists In-progress cards with no
  job and no change for more than 2 h. When the list is not empty, the timer opens one sweep session in a new
  Herdr tab. The sweep closes finished cards with evidence, starts at most 4 side sessions for agent work, and turns
  owner-blocked cards into Needs-you cards with a link. It has a 45 min deadline, never touches trading, and must
  not push, deploy or restart without a recorded owner approval. A real sweep on real idle cards was not yet
  observed (none were idle).
- **Index timers** (Live): `firstmate-index.timer` (every minute) rebuilds the report and change lists;
  `firstmate-running.timer` (every 30 s) rebuilds the Running data.

## 3. Discord bot: user-experience changes (rig)

The full list, with reasons and dates, is in the bot's own repository (`docs/UX-DECISIONS.md`). Summary
(bot service Live at the newest change, 2026-10-18):

- **Reply dashboard link.** A reply gets one dashboard link right above the spoken audio (or at the end), after a
  blank line. The plain-text label names the target: the card the reply names, a report, or "the cards changed in
  this reply". Agents name the target with hint lines (`⚓ item:<id>`, `⚓ report:<path>`); the bot removes these
  lines from the visible reply.
- **Question style follows voice.** When the owner is in the voice channel at the start of a run, the agent asks
  one plain-text question at a time (question, choices, recommendation). Otherwise it uses ask blocks (menus).
- **Ask blocks** come only through the bot's loopback `/post` with a fenced `ask` block, so they render as menus.
  Open menus are not sent again; a `Still waiting:` line links each open question by its message link.
- **📨 Queued badge.** When the owner answers a Needs-you or Open card in Discord, the bot marks the card
  "Queued: you responded" before the run starts. Only the owner's own text is scanned.
- **Ask menus survive restarts.** Open menus are saved and reloaded; a tap on a lost menu reaches the agent as a
  typed answer.
- **Restarts without starvation.** The queue is saved and restored. After 10 min of waiting, new jobs are held
  while running jobs finish (never during a voice call). Every restart passes shell, type and test checks first.
  After 2 h of a busy bot, a pending restart gives up and posts one alert.
- **Channels.** Mirrored channel names start with a topic emoji and are sorted by emoji group. Channels the owner
  moves into a Pinned category stay there. A read-only dashboard channel sits at the top of the server.
- **Channel cleanup** (Live: `channel-cleanup.timer`, daily 10:00). After 24 h without a message, a finished
  channel moves to the Archive category (never deleted) and its Herdr tab closes. Unsure channels go to the owner
  as one batched question. The coordinator, dashboard and alert channels are never touched.
- **Other:** Working… no longer pings; heartbeat flags a stuck tool (no CPU, I/O or log writes for 10 min); the
  mirror notes commits, pushes and PRs and reports a stalled tool call after 15 min; jump-link labels never show
  raw URLs.

## 4. Agent coordination (both machines; Recorded rules)

- **Fan-out.** FIRSTMATE answers quick questions itself and starts every other job in its own new Herdr/OMP side
  session, in parallel, and replies at once with what started. Jobs share one session only when they share context
  or must run in order.
- **Side sessions** start in a new unfocused pane, and the same task text is posted to the mirrored channel so the
  owner can see it.
- **Side sessions report through files.** They use defaults for routine choices and write real owner decisions to a
  handoff file for FIRSTMATE, which batches questions to the owner.
- **Dashboard on every turn.** Each owner message leads to tracker updates through `fm`.
- **Background waits need a deadline** and a progress check. When the deadline passes, the agent reports what it
  waited for and stops.
- **Access changes include our own services.** Before a permission, firewall, credential or network change, list
  every bot and service that uses the resource, give each one access in the same step, and verify each one end to
  end afterwards. Every long-running service alerts after 3 failures in a row, once per incident, with a recovery
  notice.
- **Old coordinator sessions** were retired on 2026-10-17 and fresh sessions started. The old logs are kept as
  read-only history and are never resumed.

## 6. Self-healing harness (rig, partly Mac)

Owner decisions of 2026-10-16 (Recorded) and their timers (Live on the rig, 2026-10-18):

| Unit | Schedule | Purpose |
|---|---|---|
| `harness-watch.timer` | every 2 min | Read-only watch of failing user units, bot health and disk; one alert per incident plus a recovery notice; direct-post fallback when the bot is down; daily expiry checks for logins and deadlines |
| `harness-resume-snapshot.timer` + `harness-resume-boot.service` | every 5 min; at boot | Snapshot of Herdr tabs; after a reboot, stopped OMP sessions resume in new tabs |
| `failure-digest.timer` | daily 08:00 | Groups the day's failures from OMP logs and the user journal; top 8 with suggested fixes |
| `weekly-update.timer` | Sunday 04:30 | Latest OMP, then a system update; it never reboots and reports a needed reboot |

- **Mac** (Live): `omp-latest-update.timer`, Sunday 04:30, OMP only. No unattended system updates on the Mac.
- **Latest OMP everywhere.** The updater refuses a build without credential refresh leases, restarts dependent
  services only on a version change, and checks the Claude login from metadata only.
- **Long commands** run through `longjob`, which posts a "still running" line every 5 min. Approved jobs may run
  up to 4 h.
- **Problem alerts** can start one read-only triage run in a new alert thread (at most one per problem per 6 h).
- **Retry backoff** is shared, with a cooldown per site (for example after a YouTube bot check).
- **`browser-route`** (Live: installed) prints the first healthy browser route (JEV, relay, native, screen
  control) without starting Chrome.
- **Approvals.** Agents may do routine authorized admin work directly. Sensitive actions (credentials, sign-in,
  disk encryption and boot, firewall or network exposure, user accounts, deleting data, anything hard to undo)
  need the owner's Approve button first.
- **Claude only** (owner, 2026-10-17): no planning or fallback to other paid coding-model subscriptions. Their old
  logins are kept and their errors ignored.
- Stopped agents may continue or resume on their own after errors or a reboot.

- **Restarts** ([2026-10-15](updates-2026-10-15.md), section 1): the idle restart now also drains after 10 min,
  runs checks first, and gives up after 2 h of a busy bot (section 3 here).

  no longer the preferred route. Between the two machines, copy files over SSH (`scp`, `rsync`). To the phone,
  attach the file to a Discord reply; reports go as PDF or as a page on the report server.
- **YouTube and TikTok transcription** (lessons, 2026-10-16 to 2026-10-18): request only `en,en-orig` captions
  (`en.*` triggers rate limits); when captions are rate-limited, download audio and transcribe locally. For TikTok,
  download the video with sound, because the audio-only format can be the added music.
