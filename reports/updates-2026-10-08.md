# Changes from 2026-10-04 to 2026-10-08

## Scope and evidence standard

This report adds the changes made after the [2026-10-04 update](updates-2026-10-04.md), from the late evening of 2026-10-04 to the evening of 2026-10-08. It does not replace the other reports. Where this report and an older report disagree, this report describes the newer intended state.

Sources were reviewed privately: live configuration and installed versions on both machines, the agent instruction files and their dated backups, session summaries, and the user's own requests in agent conversations. Raw conversations, logs, and private evidence are not published. Work on private software projects and the user's phone migration in the same period is out of scope, except where it changed the shared environment.

Each item has a status:

- **Live (2026-10-08):** the setting, file, version, or service state was checked on that date.
- **Recorded:** the rule or result is written in the agent instructions, lessons, or task records; the live effect was not checked again for this report.
- **Open:** requested or partly done; the outcome is not confirmed.

"Mac" means the native Linux/aarch64 laptop role. "Rig" means the x86_64 workstation role. "Both" means both machines. Paths are home-relative.

Remote-access items (phone pairing, VPN, public-address reachability) are described only as capabilities. Their addresses, keys, and exposure paths are not published.

## 2. Herdr and the Heeler phone app

**Heeler** is an independent iOS companion app for Herdr. It shows the agents on each machine and lets the user read and steer their terminals over SSH. Its Herdr plugin (`heeler` 0.6.0) is installed on both machines; it provides QR pairing, agent notifications, and a sidebar-layout snapshot for the app.

- **Pairing** (Both, 2026-10-08; Recorded). One Pairing Code adds one machine, so each phone needs one code per machine. After pairing, each machine's `authorized_keys` has one `heeler` line per phone. The default code lifetime is 120 seconds, which is too short for delivery by email; a one-shot run of the plugin's own pairing functions with a 600-second lifetime worked. The code contains a private bootstrap secret: never print it or store it in logs; write it only to private (0600) files and delete them afterward. A pairing attempt fails if the phone cannot reach the machine's SSH server yet (for example, before the phone joins the private VPN).
- **"The SSH connection is unavailable"** (Recorded). Heeler shows this when it saves a machine's notification settings while that machine is disconnected. Check the SSH server log for the phone's login before suspecting keys.
- **Agents-list layout** (Both, 2026-10-08; Live). The plugin accepts only Herdr's built-in sidebar tokens and the style keys `token`, `fg`, `bold`, and `dim`. The custom row `{ token = "machine", rules = [...] }` (a colored Mac/Rig label) failed its check with `invalid_schema`, and the app fell back to the default layout and showed a configuration warning. At the user's choice, the label was removed on both machines. `[ui.sidebar.agents]` now has the rows `["state_icon", "workspace", "tab"]` and `["agent"]`. The host cue in the tab bar is unchanged. Each machine has a backup `~/.config/herdr/config.toml.bak.heeler-<time>`. The plugin keeps its snapshot in `~/.config/herdr/plugins/config/heeler/sidebar.json` and regenerates it only when the config file's modification time changes or the plugin starts. After a config change, run the plugin's `src/sidebar-hook.js` once with `HERDR_PLUGIN_CONFIG_DIR` set, then check that `diagnostics` is empty.
- **Dictation on the phone** (2026-10-08; Recorded). Heeler removed its own hold-to-talk dictation in an earlier release. iOS keyboard dictation typed straight into the live terminal (Direct Input) repeated every partial result ("cacan yocan you…"). The likely cause is that each dictation update reaches the terminal as new input without deleting the previous one; the app source was not checked. Use the **Composer**, the draft field below the terminal: dictate there, then tap **Send** once. The Composer's tools keyboard sends arrow keys and other control keys straight to the agent without changing the draft, so menu choices and custom answers do not need a view change. If the agent is blocked on a question, **Send** inserts the draft without Enter; submit it with the tools keyboard.
- **Workspace names follow folders** (Both, 2026-10-08; Live). The Mac's only workspace was called `Local ~`, which appeared as "Mac → Local ~" in the rig's machine tree. Its panes are in the home folder, so it was renamed `Home` with `herdr workspace rename`. New rule: name Herdr workspaces after the top-level folder they work in (for example Github, Games, TMP) and use `Home` only for a workspace that is really in `~` (section 8).
- **Agent tabs after a restart** (Rig, 2026-10-05; Recorded). After the restart, each Herdr agent tab was restarted and its matching saved OMP session was resumed. A tab without a matching saved session kept a new, empty session.

## 3. Rig hardware and power

- **RGB lighting off at every boot** (Rig, 2026-10-06; Live unit, Recorded effect). The system unit `omarchy-rgb-off.service` (enabled, `WantedBy=multi-user.target`) runs `/usr/local/sbin/omarchy-rgb-off`, which turns off the internal RGB lighting and the liquid cooler's LCD. `openrgb.service` stays disabled. Whether the lights stay off after a cold boot was not checked for this report.
- **Unattended start after a power cut** (Rig, 2026-10-07; Recorded). The rig's root disk is encrypted and asks for its password before networking starts, so after a power cut the rig stays offline until someone types the password at the machine. The BIOS "restore on AC power loss" setting alone is therefore not enough. An unattended start also needs an unlock method, for example TPM2 auto-unlock (this also needs a change of initramfs hook) or SSH unlock from the initramfs on the home network. Both are security choices that the user must make; neither has been applied. The user decided not to buy an IP KVM.
- **Reach from outside the home** (Recorded). Only the private VPN is known to reach the rig from outside. Tests through the home public address failed, and a Wake-on-LAN packet sent to that address had no effect.
- **Reminders at a clock time** (Mac, 2026-10-07; Recorded). `omarchy-reminder <minutes>` uses a timer that pauses while the laptop sleeps. For a reminder at a fixed time, create the same reminder unit with a calendar time and its message file, so `omarchy-reminder show` and `clear` still find it.

## 4. Menus and input

- **Trackpad toggle** (Both, 2026-10-07; Live). The pointing device is called "Trackpad" in menus. **Trigger › Hardware › Trackpad** turns it on and off (`omarchy-toggle-touchpad`), and `Super+Ctrl+H` opens that Hardware menu. Both machines have the same overrides in `~/.config/omarchy/extensions/omarchy-menu.jsonc`. The row appears only where a touchpad is detected, so it is normally hidden on the rig. Omarchy's own on-screen message still says "Touchpad".
- **Menu overrides replace the whole entry** (Both, lesson 2026-10-07). An entry in `omarchy-menu.jsonc` that reuses a default ID replaces that entry; missing fields become blank. A label-only override removed the action and condition and hid the row. Restate every default field (icon, label, when, action, checked, aliases) and change only what you mean to. The menu reloads when the file is saved, so check the merged result with the menu plugin's own `parseMenuJsonc` and `mergeMenuSources` functions right away.

## 5. Browser and agent control

- **One Browser Relay port per machine** (Both, 2026-10-07 and 2026-10-08; Recorded). The Chrome relay extension connects to one fixed local port. On the rig, a separate automation tool uses the same relay as a client: it reuses a running relay and starts one only if none is running. Do not move that tool to another port, because it would lose its connection to Chrome. The user decided to keep the shared port.
- **Relay version must match the sessions** (Both). Start the relay with the same `omp` binary that the sessions run (`readlink /proc/<omp pid>/exe`); otherwise sessions report an outdated relay. The extension files on both machines were reinstalled from the 18.6.1 build and reloaded in Chrome. `browser.relay` is `false` on both machines, so the extension badge shows "off" until something starts a relay.
- **No rendering tests on the Mac** (user instruction, 2026-10-07; Recorded). Run GPU-heavy, WebGL/WebGPU, and browser-performance tests on the rig, for example in a headless Chrome there that uses the real GPU, driven through a forwarded DevTools port. Do not load test pages, headless browsers, or benchmarks on the Mac unless the user asks again. Mac Chrome reports `navigator.gpu` but gets no WebGPU adapter, so pages fall back to WebGL2.
