## 2. Discord as the remote control surface (rig)

A Discord bot on the rig (`omp-discord-bot`, user service) is now the main way to talk to OMP from the phone. (Live unless noted.)

- **Owner-only, private server.** Only the owner's Discord account is routed to agents. Bot replies pass a privacy filter.
- **Tab mirroring.** Every OMP tab in Herdr on both machines gets its own Discord channel in a 🖥️ Rig or 💻 Mac category; closed tabs move to 📦 Archive. Terminal replies appear in the channel within about 1 second; new or closed tabs sync within about 15 seconds. A message sent in a channel continues that tab's session when no OMP is running in it, otherwise it runs in a linked side session. The bot never types into a pane.
- **Trusted mode** (owner decision 2026-10-13). Discord runs are not sandboxed and follow the same rules as a terminal session. Switch: `scripts/trusted.sh on|off|status` (the flag file plus a passwordless-sudo drop-in; `off` removes the drop-in first). The earlier sandboxed model (read-only repos, blocked SSH/IBKR/op, password-gated approvals in a Herdr tab) remains in the code and returns when trusted mode is off.
- **Approve button.** `omp-approve` now posts the exact command with an Approve button in the thread (owner only, single use, hash-checked). In trusted mode it is used only where a terminal session would need a password or sign-in.
- **Questions as menus.** `omp -p` has no `ask` tool. A run ends its answer with a fenced `ask` JSON block; the bot shows each question as a select menu and sends the picks back as the owner's next message. Typing a normal message is the "other" answer.
- **Copy and send.** Paste-ready blocks are posted as their own messages (long-press Copy Text copies only the block). A "Send to FIRSTMATE" button delivers text only when that pane is idle with an empty input line.
- **HEELER links.** Buttons open the right agent pane in the HEELER iOS app through a small redirect page (Discord does not allow custom-scheme buttons).
- **Attachments.** An answer line `📎 attach: <path>` uploads a file (≤ 10 MB, ≤ 10 files), only from user content folders and `/tmp`; secret-looking files and protected folders are refused.
- **Voice messages.** Transcribed locally with faster-whisper on the rig GPU (`omp-whisper` user service keeps the model loaded, about 1 GB VRAM; about 0.6–0.9 s per message, CPU fallback). The transcript is shown in the thread and used as the typed message. Nothing is sent to an outside speech service. Claude models do not accept audio input, so this step is required.
- **Links.** Long URLs in replies become short masked links without previews.
- **Restarts.** `scripts/safe-restart.sh` health-checks the bot and on failure reverts the given commit and turns trusted mode off. `scripts/restart-when-idle.sh` waits until no run is active (a run cannot restart its own bot).
- **Bot identity.** Name "OMP 🤖", avatar from the upstream OMP icon.

## 3. Notifications: Discord replaces ntfy

(Live 2026-10-13, both machines.)

- The shared OMP notification sender posts to a private `#omp-alerts` channel. The rig posts to the bot's loopback endpoint; the Mac posts over its existing SSH route to the rig. `OMP_NOTIFY_TRANSPORT=ntfy` restores ntfy.
- Trading-bot alerts post to a private `#trading-alerts` channel.
- Both alert channels sit in a 🔔 Alerts category at the top of the server.
- ntfy `enabled` is `false` on both machines after a verified cutover test (one real post on each path). Exception by design: urgent trading alerts still go to ntfy at top priority when the Discord post fails.
- Limit: if the bot is down, non-urgent alerts are not delivered anywhere.

## 4. Desktop and input

- **Moonlight pointer speed** (rig, Live). The Sunshine virtual mouse sensitivity changed from −0.5 to 0.0 (normal) so iPhone Moonlight travel is longer; the Mac trackpad over Moonlight is faster as a side effect.
- **iOS Moonlight tips** (Recorded): set On-Screen Controls to Off to remove the gamepad overlay; a three-finger tap opens the keyboard.

## 5. Crash diagnosis rule (both, Recorded)

After a crash diagnosis, the agent files an evidence-backed GitHub issue in the most relevant repository without asking (no secrets, core dumps or private data), then closes only its own crash-diagnosis terminal window after the report is saved. The Mac FEX update crash (16 KiB page size, x86_64-only AUR Wispr package under `yay --noconfirm`) recurred on 2026-10-10 and was filed upstream.

## 6. Agent working rules (both, Recorded)

- Notifications never echo the user's own prompt; they show the agent's reply, question or pending action.
- Text the user must paste goes in its own message with nothing else in it.
- Interactive questions always include an "Other (type a reply)" option.
- Do the follow-up work in the same turn instead of promising to do it "next".
