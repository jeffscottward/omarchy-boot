# Changes after first publication (2026-09-21 to 2026-09-28)

## Scope and evidence standard

This report adds the customizations made after the first public version of these documents (2026-09-21). It does not replace the other reports. Where this report and an older report disagree, this report describes the newer intended state.

Sources were reviewed privately: live configuration on both machines, the agent instruction files, task checkpoints, and the user's own requests in agent conversations. Raw conversations, logs, and private evidence are not published.

Each item has a status:

- **Live (2026-09-28):** the setting was checked in the live configuration on that date.
- **Recorded:** the rule or result is written in the agent instructions or task records; the live effect was not checked again for this report.
- **Open:** requested or partly done; the outcome is not confirmed.

"Mac" means the native Linux/aarch64 laptop role. "Rig" means the x86_64 workstation role. "Both" means both machines. `<local-namespace>` replaces a personal plugin prefix. Paths are home-relative.

Security-sensitive remote-access items are described only as capabilities. Their mechanisms, service names, addresses, and exposure paths are not published. Provision them privately on a new machine.

## 1. Keybindings

| Keys | Action | Scope | Status |
|---|---|---|---|
| `Super+Shift+T` | Toggle the window between floating and tiling (was `Super+T`) | Both | Live |
| `Super+Shift+L` | Toggle the workspace layout (was `Super+L`) | Both | Live |
| `Super+Shift+C` | Open clipboard history (`omarchy.clipboard`); replaces the stock calendar shortcut | Both | Live |
| `Super+Shift+F2` | Open the keyboard context menu (sends `Shift+F10` with Hyprland `send_key_state`) | Both | Live |
| `Super+Shift+F3` / `F4` / `F5` | Full-screen screenshot / region screenshot / screen recording | Both | Live |
| Bare `F3` / `F4` | Toggle floating / open the Omarchy menu | Both | Live |
| `Alt+Tab`, `Alt+Shift+Tab` | In the Herdr terminal window: next/previous Herdr tab. Elsewhere: cycle windows | Both | Live |
| Lid switch | Runs the Lid Lock policy script (see section 7) | Both | Live |

Notes:

- The stock `Super+Ctrl+Shift+3/4/5` capture shortcuts are unbound. On the rig, the older four-modifier capture row in the desktop report is obsolete.
- **Mac function row.** The top row sends media keys by default (`hid_apple fnmode=1`). The same actions are also bound to the physical top-row keys by their media keysyms (`XF86LaunchA` = F3, `XF86Search` = F4, `XF86AudioMicMute` = F5, brightness-up = F2), so no `Fn` chord is needed.
- **`Fn` is reserved for dictation.** On the MacBook keyboard, `Fn` triggers voice dictation. Do not design shortcuts that need `Fn`. The convention is `Super+Shift+<physical key>` where a `Fn+<key>` chord would otherwise be used. When an application shortcut needs a function key, first use a non-function-key alternative (for example Chrome's `Shift+Alt+T` instead of `F10`).
- **Mac trackpad.** Tap-to-click is on (`tap_to_click = true` for the built-in trackpad in `~/.config/hypr/input.lua`).
- **Notifications.** `Super+,` dismisses only the newest toast. A critical notification with no timeout stays until dismissed, so other toasts can be dismissed first. `Super+Shift+,` dismisses all (not tested for this report).

Keybinding changes are tested on the rig first, then applied to the Mac.

## 2. Terminal and Herdr

In `~/.config/herdr/config.toml` on both machines:

- `alt+tab` / `alt+shift+tab`: next/previous tab (the prefix keys remain).
- `alt+a` / `alt+shift+a`: next/previous agent.
- `alt+w` / `alt+shift+w`: next/previous workspace.
- `ctrl+shift+up` / `ctrl+shift+down`: page the selected pane up/down. Two `[[keys.command]]` entries call a small helper, `~/.local/bin/herdr-page-scroll`.
- On the Mac, the old `alt+left` / `alt+right` tab keys were removed so that word navigation works.

Other changes:

- **One session name.** The terminal launcher uses the Herdr session `default` on both machines. The Mac previously used `local`. (Live)
- **New-tab layout (Mac).** The bottom terminal pane in a new tab is larger: the split ratio changed from 0.85 to 0.75. (Live)
- **Remote logins.** An interactive SSH login to the Mac now opens Herdr, as on the rig. A local desktop terminal is unchanged. (Live)
- **Clickable links.** The agent TUI setting `tui.hyperlinks: always` plus a small Herdr plugin (`local.file-links`) make file paths clickable. File links are revealed in the file manager, never executed. Web links use Ctrl+click. (Live)
- **Moving tabs between workspaces.** `herdr pane move --new-tab --workspace <name>` works on the installed Herdr version. (Recorded)
- **Stale prompt fragments.** If agent prompts reprint after switching the viewed machine, reload the selected endpoint (`prefix+q` or `herdr server reload-config`). This is a workaround; the cause is not confirmed. (Recorded)

## 4. Voice, dictation, and clipboard

- **Wispr Flow on both machines.** The rig now runs Wispr Flow as well as Voxtype; older reports describe the rig as Voxtype-only. (Live)
- **Clipboard-preserving dictation.** The unofficial Linux Wispr Flow build pasted dictated text through the clipboard and did not restore it. The accepted fix is a privately patched native helper and application patches, started through a `~/.local/bin/wispr-flow` wrapper (`--print-launch-plan` shows the route without launching). The helper saves every clipboard format, marks dictated text so clipboard history skips it, pastes multiline and tab text, and restores the previous clipboard after about 750 ms. A later repair stopped it from leaving `Ctrl`/`Super` held down after a paste. (Recorded; wrapper and routing Live)
  - Build each architecture natively. Never copy the aarch64 build to x86_64 or the reverse.
  - The build is pinned to one upstream version. An upgrade needs a deliberate rebuild and re-patch.
  - A single-line-only workaround was rejected, because lists and tabs must dictate correctly.
- **Recovery.** If dictation fails with a "clipboard snapshot timed out" error, the fastest known safe recovery is: let the user save anything important, copy a harmless fresh text, and retry once. Record every agent-made clipboard change per machine (diff, backup, activation state, rollback). (Recorded)
- **Apple Silicon package note.** An x86_64-only package recipe for the dictation app ran through FEX emulation on the Mac and aborted during extraction. A 16 KiB host page size is a strong lead but not a proven cause. Use a native aarch64 route on the Mac. (Recorded)
- **Text to MD5.** A small GTK tool (`Super+Ctrl+M`, or **Text to MD5** in the launcher) hashes the exact typed text locally. **Copy** / `Ctrl+Enter` now uses `wl-copy --sensitive`, so Omarchy's clipboard history (which skips `x-kde-passwordManagerHint`) does not keep the result, but pasting still works. Plain `Enter` inserts a line break, which changes the hash; the byte counter shows it. (Live, both)
- **Batch transcription** jobs must not depend on, inspect, or stop the dictation app. (Recorded)

## 5. Browser and extensions

- **Browser automation for agents.** Playwriter is retired. Interactive browser work uses **JEV for Chrome** through a local MCP adapter, which drives one selected tab within named origins and asks the agent to approve each proposed action. The fallback order is: direct CLI/API, then a guarded desktop-control skill (`drive-screen`), then the human. The agent's MCP servers are now `context-mode` and `jev` on both machines, plus `grep-app` (rig) or `hyperresearch` (Mac). (Live)
- **Privacy boundary.** JEV sends page observations to an external decision service. Use it only on public pages and ordinary authenticated dashboards needed for the task. Never use it on banking or other financial pages, secret-bearing pages, vault contents, or highly sensitive personal data. (Recorded)
- **Main Chrome profile on both machines:** JEV for Chrome, **Unclutter** (hides ads and cookie walls with reusable, AI-reviewed page-template rules; loaded as an unpacked build), and the **1Password** extension. Each machine uses its own provider keys; no keys are stored in this repository. On the rig these were set up on 2026-09-28 and shown working: Unclutter hid 43 elements and the cookie wall on a news home page, and the JEV built-in flight-search example reached a results page. (Live)
  - Branded Google Chrome ignores `--load-extension`, and Chrome 136+ does not allow remote debugging of the default profile. Load unpacked extensions from `chrome://extensions` → **Load unpacked**.
  - JEV's optional text helper uses the model `google/gemini-3.8-flash` through OpenRouter.
- **Keyboard access to an extension.** `Shift+Alt+T` focuses the first Chrome toolbar item (`F10` focuses the last one, on keyboards where it does not need `Fn`). Arrow or Tab to the puzzle-piece Extensions button, press Enter, and choose the extension. Pin extensions for faster access.
- **Login etiquette with 1Password.** The agent uses 1Password autofill for the requested site. If 1Password is locked, the agent may open the unlock prompt, but the human types the master password. For Google two-step verification, try the passkey first; otherwise use **Try another way** and approve on a second device. (Recorded)
- **Required pages.** When a task needs a web page, the agent opens or focuses that exact page instead of only pasting its URL. (Recorded)

## 6. Notifications and remote use

- **Agent notifications** (ntfy, sent from agent lifecycle hooks on both machines): the title shows the source, machine, workspace, tab, and a status emoji. The body shows a short preview of the task, result, or needed action, and tapping it can open a remote terminal. Raw credentials are never included. For a human wait with no hook (for example an external password prompt), the agent sends one notification with the needed action. Notification topics and destinations are private; provision them separately. (Recorded)
- **Spoken notifications (Mac).** Completion notices are spoken with the local Kokoro-82M "Heart" voice (`~/.local/bin/omp-notify` → a `voice-notify` dispatcher). eSpeak NG was rejected and removed. (Live)
- **Remote use of the rig from the Mac.** Moonlight streaming and phone monitoring of agents are configured. Provision the streaming host, pairing, and any phone access privately; no endpoints are published here. Do not edit `Moonlight.conf` with `kwriteconfig6`; it damages the saved host entries. (Recorded)
- **Authentication inside the terminal session.** When an authorized task needs a password or interactive setup, the agent opens a new Herdr pane below its own pane (or a new tab in the same session), so the prompt is reachable remotely. The new pane is created with agent auto-start turned off and is checked to hold a plain shell before any command is sent. The agent never reads back that pane, and closes only panes it created. (Recorded on the rig; the Mac's instruction file still has the older rule)
- **Remote agent sign-in (OAuth).** When the agent on one machine waits for a `localhost` OAuth callback but the browser is on the other machine, forward that port over SSH (`ssh -L`) and open `http://localhost:<port>/launch` in the local browser. Sign-in stays human-only. Close the tunnel afterward. (Recorded)
- **Unattended reboot (optional).** A machine can be set to boot without typing the disk password, keeping the password as a fallback. Decide this per machine and provision it privately: it reduces protection if the hardware is stolen. (Recorded)

## 7. System and power

- **Lid Lock** (`~/.local/bin/omarchy-lid-lock on|off|toggle|status`) sets a lid-only lock/suspend policy and has a **Setup → Lid Lock** toggle. Idle and manual locks are not affected. Choose the lid state per machine; turning lid locking off reduces protection for an unattended laptop. (Live)
- **Project servers use Portless.** Agent-started project servers get stable, human-readable names (`*.localhost`) instead of raw ports, through a `portless-proxy` user service. `.localhost` resolves on the local device only. Access from a phone or another computer needs a protected, scoped front door. Never use wildcard hosts, all-interface binding, or Internet exposure to make it work. (Live/Recorded)
- **New command-line tools:** `gws` (Google Workspace CLI; the agent uses it only for read-only checks that a task email arrived), `llmfit` (checks which local models fit the hardware), `omarchy-jev` (a structured, screenshot-free desktop-control driver for agents, published separately), and `portless`. Local image-generation tools were also installed; they are outside this report. (Live)
- **Rig shell:** `mise use -g rust@stable` fixed a Rust shim error in the prompt. (Recorded)
- **Removed from the rig:** the Punktfunk packages. The rig's Omarchy menu still has stale Punktfunk entries. (Live)
- **Mac packages:** `snapper`, `grub-btrfs`, `limine`, and `limine-snapper-sync` were installed, but the active boot loader is still GRUB. It is not known whether a boot-loader change was intended. (Live/Open)

## 8. Agent (OMP) configuration and working rules

**Configuration** (`~/.omp/agent/config.yml`, Live, both): the default model role is an Anthropic model with an advisor role enabled and automatic thinking level. JEV is the "judge" role for typed decisions. Other settings: `startup.quiet: true`, `symbolPreset: nerd`, `tui.hyperlinks: always`, `computer.enabled: true`, and extensions for context-mode, ntfy, and browser routing. The installed OMP versions differ between the machines.

A privately patched OMP build added `Shift+Left/Right` text selection in the input line (Esc returns to the selection start). A `~/.bashrc` wrapper uses it only for the exact version it was built from. The machines now run other versions, so stock OMP is in use. Rebuild the patch or confirm upstream support before relying on it. (Live/Open)

**Working rules** added to `~/.omp/agent/AGENTS.md` (Recorded, both unless noted):

- **Routine autonomy.** Finish already-authorized routine steps without asking again. Ask only for genuine blockers, desktop handover, extra authentication, or security and consequential approvals.
- **Scope checks.** Before each substantial work package or scope expansion, ask an advisor to challenge the scope: name the deliverable, the stop condition, the evidence for any dependency, and a simpler path. Park unproven dependencies.
- **Lesson persistence.** Save confirmed, reusable lessons without being asked. Keep facts separate from hypotheses, update stale entries, never save secrets, and tell the user what was saved and where.
- **Reply style.** Use meaningful status emojis (✅ ⚠️ ❌ 🔧 🧪 ✍️ 🔐) with short sections and bullets. Never rely on an emoji alone for a warning, and never put emojis in code or commands.
- **Email checks.** Use the Workspace CLI for narrowly scoped, read-only checks that a task email arrived. Never use links or codes from those emails.
